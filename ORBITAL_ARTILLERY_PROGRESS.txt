PROJECT STRUCTURE
==================================================
Frontend repository:
- wzzzodiac/orbital-artillery
- Browser client
- Vanilla HTML/CSS/JavaScript + Canvas 2D
- Intended for GitHub Pages

Server repository:
- wzzzodiac/orbital-artillery-server
- Node.js + Socket.IO
- Authoritative multiplayer state and gameplay resolution
- Intended for Google Cloud Run
- In-memory rooms for MVP
- No accounts / no persistent DB in MVP

Core design:
- 2–8 players
- Private room codes
- Temporary player names
- Turn-based 2D artillery
- Server authoritative

PHASE 6A — PICKUPS / INVENTORY / HEAVY BOMB — COMPLETE
Core inventory model:
- Slot 1 = permanent basic weapon.
- Slot 2 = inventory item.
- Slot 3 = inventory item.
- Therefore: 2 pickup inventory slots + basic weapon.

Pickup rules currently implemented:
- Spawn periodically during match.
- Current cadence: every 3 turns.
- Current lifetime: 4 turns.
- Maximum simultaneous pickups: 2.
- Pickup by touching/movement.
- Pickup by explosion if inventory space exists.
- Successful pickup-via-shot can preserve the active turn.

Heavy Bomb:
- High-damage special projectile.
- Current server values around Phase 6A:
  - max damage 60
  - explosion radius 320
  - crater radius 190
  - crater depth 90

Other work:
- Weapon selection HUD moved outside arena.
- Numeric weapon selection 1/2/3.
- Reliable click selection fixes.
- Explosion knockback implemented and animated ballistically.

--------------------------------------------------
PHASE 6B — TRIPLE SHOT / CLUSTER BOMB / SHIELD — COMPLETE
Triple Shot:
- Three-projectile volley.
- Side projectiles currently offset around ±6 degrees.
- Lower per-projectile damage; intended for area coverage.

Cluster Bomb:
- Parent projectile followed by multiple local impacts.
- Current secondary offsets: approximately -180, -90, 0, +90, +180 around impact center.
- Multiple explosions/craters.

Shield:
- Pickup utility.
- Current damage factor: 0.5 (50% damage received).
- Consumed when it absorbs damage.
- Activating Shield does not end the offensive turn.

Turn-flow refinements:
- Shield activation keeps controls active.
- Successful pickup shots can keep turn alive.
- Match starts and spawn positions randomized.

==================================================
CURRENT GAMEPLAY LOOP
==================================================
Already functional in broad form:

Create room
-> join players
-> select mode/team/terrain
-> ready/start
-> spawn
-> alternate authoritative turns
-> move/jump
-> aim/power/wind
-> shoot
-> projectile resolves on server
-> terrain can deform
-> players take damage / get knocked back / fall
-> pickups appear
-> inventory/special weapons are used
-> players die
-> survival/team winner is determined

This is no longer a networking scaffold. It is a playable core loop requiring continued feature work, balancing, QA and presentation/mobile polish.

KNOWN ORGANIZATIONAL RULES
==================================================
1. The server must remain authoritative for gameplay-critical state:
   - turns
   - damage
   - inventory
   - projectile resolution
   - pickup resolution
   - death
   - victory

2. Do not trust client state for gameplay outcomes.

3. Keep MVP architecture simple:
   - no account system unless deliberately added later
   - no DB unless persistence becomes necessary
   - private room codes first

4. Before implementing a new feature, verify current code/commits in BOTH repositories.

5. Whenever a phase or major subphase is completed, update this file and README.md in the same development session.

6. Keep COBY_DEBUG.txt updated when workflow, repository structure, debug procedure or resume instructions change.
