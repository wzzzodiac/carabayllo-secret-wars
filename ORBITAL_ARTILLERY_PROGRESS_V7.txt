COBY DEBUG V7 — CONFIRMED FIXES
==================================================
1. INVALID TRAVERSAL STATE MUTATION
Before fix:
- Phase 6D free-movement wrappers expanded movementRadius/jumpsRemaining before base validation.
- A non-active/spectator move or jump could be rejected correctly but still mutate shared traversal bookkeeping.
Fix:
- snapshot traversal state before compatibility override.
- restore snapshot on failed base movement/jump.
- expose free-traversal state only after successful actions.
- public Phase 6D state now reports movementRadius/jumpsRemaining as null rather than leaking old Phase 4 values.
Regression added for spectator move/jump rejection without state mutation.

2. NUKE OVERLAY CAMERA DIVERGENCE
Before fix:
- renderer6d.js used an independent fixed approximate 1000x1000 view.
- base renderer uses real zoom, transitions, projectile follow and manual drag.
- therefore Nuke overlay geometry could diverge from the world under non-default camera state.
Fix:
- base renderer now exposes getViewSnapshot().
- renderer6d uses the exact base camera view for all world-to-screen Nuke overlay transforms.

3. NUKE BEAM / TERRAIN-BAND GEOMETRY
Before fix:
- Nuke beam was very steep/near-vertical while terrain destruction was a large horizontal support cut.
Fix:
- current beam vertical half-span: 320 world units.
- horizontal half-length: 900 world units before edge clamping.
- visual beam is still diagonal but now crosses the same broad terrain band the weapon destroys.
Regression checks major width and bounded vertical spread.

4. FREE JUMP INTO VOID TIMING
Before fix:
- Phase 6D shortened every server motion.type='jump' to 500 ms.
- core void-jump death also uses type='jump' with toY beyond the world.
- jumping into a gap could therefore visually finish in ~0.5 s while death resolution still used the long fall timing.
Fix:
- only non-void jumps are shortened to 500 ms.
- jumps whose toY is beyond WORLD_HEIGHT retain the core long fall/death motion.
Regression added for a jump into the Terraces central gap.

5. PHASE 6D FRONTEND IDENTITY CLEANUP
Fixed during the audit:
- base renderer now has native Nuke pickup style instead of falling back to Heavy style.
- Nuke aim/designator preview is magenta.
- designator no longer renders a fake Basic explosion at impact.
- countdown overlay now says PHASE 6D and includes Nuke Laser instead of stale PHASE 6C.2 text.
- frontend cache-busting advanced to worldender-3 for corrected renderer chain.

CURRENT PHASE 6D NUKE DESIGN
==================================================
Rarity:
- Nuke weight 3 in current pre-final pool total 126.

Targeting:
- normal authoritative artillery projectile is the designator.
- angle/power/wind affect it normally.
- impact locks target.
- spectators receive live authoritative aim state.

Timing:
- warning after target lock: 3000 ms.
- sustained beam: 3000 ms.
- afterglow/resolution buffer: about 1500 ms.

Geometry:
- horizontal half-length: 900.
- vertical half-span: 320.
- direct beam half-width: 115.
- terrain cut radius: 145.
- terrain cut depth: 4200.
- terrain cut step: 105.

Damage/rules:
- 20 direct HP.
- full self/friendly fire.
- Shield halves direct hit and is consumed.
- no conventional knockback.
- terrain-caused falls are intentional.
- intersected pickups are destroyed, not collected.
- Nuke always ends offensive turn after resolution if match continues.
