==================================================
PROJECT OBJECTIVE
==================================================
Browser/desktop 2D turn-based multiplayer artillery game inspired by Gunbound/Wild Ones.
- 2–8 players.
- Team and Survival modes.
- Private room codes.
- Authoritative server.
- Destructible 2D terrain.
- Camera overview/zoom/follow/manual drag.
- Turns, wind, movement, jumping, aiming, power, projectiles, pickups and special weapons.
- Desktop/web is the target. No mobile gameplay release is planned.

ARCHITECTURE / DEPLOYMENT
==================================================
Frontend:
- GitHub Pages.
- Vanilla HTML/CSS/JavaScript.
- Canvas 2D.
- Socket.IO client loaded on demand.
- Opening the page does not intentionally wake Cloud Run; connection starts on CREATE/JOIN.

Backend:
- Node.js + Socket.IO.
- Authoritative room/game state.
- In-memory rooms; no DB in MVP.
- Cloud Run target in us-east1.
- public/unauthenticated service.
- CORS constrained to configured client origin.
- Port 8080 default.
- GitHub/Cloud Build deployment workflow was established; do not assume deployment finished without verification.

Known server limits/defaults from current config:
- max players: 8
- max rooms: 20
- max concurrent sockets: 64
- connection attempts: 20/minute per IP
- packet limit: 30/second
- idle socket timeout: 30 minutes outside countdown/started matches
- countdown/started matches protected from idle timeout

PHASE 6B.1 — AFK SKIP VOTE — COMPLETE
- opens with 20 s remaining
- living non-active players can vote
- active player cannot vote own skip
- F1 toggles vote
- strict majority: floor(eligible/2)+1
Examples:
- 2 total alive: 1/1 spectator vote
- 3 total alive: 2/2
- 4 total alive: 2/3
- 5 total alive: 3/4
- valid active-player activity clears votes
- invalid actions do not count as activity
- majority skips immediately
- HUD skip message
- F1 reserved during match
- voter disconnect recalculates majority
- pending skip cancelled by active activity
- no double turn advance

==================================================
DESIGN DECISIONS / NON-BUGS
==================================================
1. STARTER WEIGHTING IS INTENTIONAL.
Current design intentionally gives host lower starting probability.
Examples:
- 2 players: host 40%, other 60%
- 3 players: host 20%, others 40/40
General implementation uses hostWeight=0.4/(n-1), with remaining probability shared by non-hosts.
Do not "fix" this unless Walter changes the design.

2. DESKTOP/WEB TARGET.
No mobile/touch gameplay release is planned. Responsive CSS may exist, but mobile controls are not roadmap requirements.

3. AIR STRIKE FALL/MULTI-SHELL PRESENTATION.
Static review raised possible concerns, but these are NOT confirmed bugs. They belong in manual PC QA until reproduced.
