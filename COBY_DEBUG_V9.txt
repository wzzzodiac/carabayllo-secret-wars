CONFIRMED FINDING FIXED
A1 — INTERNAL PICKUP ROLL BOOKKEEPING LEAKED INTO PUBLIC STATE
Root cause:
- Phase 6A/6C/6D/6E pickup objects carry server-only flags such as phase6cPoolRolled, phase6dPoolRolled and phase6ePoolRolled.
- inherited public pickup mapping spreads pickup objects, so those implementation flags could be serialized to clients.
Impact:
- no gameplay authority bug, but server-private normalization bookkeeping was unnecessarily exposed and created an avoidable state-contract inconsistency.
Fix:
- Phase 6E public state now strips phase6cPoolRolled / phase6dPoolRolled / phase6ePoolRolled from public pickup objects.
- internal room pickup objects keep the flags so one-time normalization behavior is unchanged.
Regression:
- balance.test.js now asserts that public pickup objects contain none of those flags while the authoritative room object retains phase6ePoolRolled=true.
- latest Server CI after the regression: SUCCESS (commit 3ff74feb7003c421ec0a93d7acb9836b5d89e074).
